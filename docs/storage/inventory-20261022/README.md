# Storage consumer inventory refresh, 2026-10-22

## Result and boundary

This additive checkpoint scans **12,738 source/configuration/tool files** at **14 immutable source commits**: 12 current default-ref snapshots, Garden-Controller's RiscRTE product branch, and Productivity's pinned CrossPoint upstream. It records **4,267 candidate-bearing files**, not that many consumers or defects. RiscRTE-3D is separately recorded as empty, with no refs, rather than passed or inaccessible.

All RiscRTE applications and device classes remain in scope. Discovery determines evidence coverage, never a limit on the required work. This is a source inventory, not migration closure, release parity, semantic qualification or a hardware test. No repository is certified fully migrated by these pattern matches.

## Reproduction and qualification

Check out the repositories at the commits in [sources.json](sources.json), preserving the repository basenames under one directory. Git objects, not the worktree or index, supply all evidence. Replacement-object behavior is disabled for every Git invocation. Run:

```sh
python scripts/audit_storage_refs.py --manifest docs/storage/inventory-20261022/sources.json \
  --checkout-root /path/to/repositories --output-dir /tmp/storage-evidence
python -m unittest discover -s tests -p test_storage_ref_inventory.py -v
python -m unittest discover -s tests -v
```

Compare generated JSON bytes and report_sha256 fields with [evidence/index.json](evidence/index.json). The source manifest's canonical SHA-256 is also pinned there. The scanner is not a network repository-discovery tool; incomplete input manifests must never be reported as global closure.

Independent review found that the first scanner checkpoint c4f8a1 allowed Git replacement refs to substitute bytes behind an original blob ID. Commit 8118cbab disables replacement objects and adds a reproducing regression. Its [hosted inventory qualification](https://github.com/michaelrolphone-cmyk/RiscRTE-System-Apps/actions/runs/39804469395/job/119913867370) passed. That is predecessor qualification only; the final report tip must be checked independently. Final local and hosted observations are recorded in [qualification.json](qualification.json), without implying all unrelated repository CI or target/hardware qualification passed.

Only inventory tooling, tests, a read-only CI workflow and additive evidence change here. No application/provider behavior, SDK/frozen baseline, release catalog, firmware or device is changed.
