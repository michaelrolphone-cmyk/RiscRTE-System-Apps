# Optional generic canvas provider

This additive provider implements the separately reviewed `ui.canvas@1` boundary. It does not replace existing scene services, native applications, model loaders or game engines. Source lineage is the existing CanvasApp logical-frame/presentation ownership and touch mapping, existing scene provider authority checks and independently rotated presentation policy, and PortableSafeViewport inset validation. Existing app-linked CanvasApp remains untouched until each consumer migration is qualified.

Content uses responsive or explicit FIT/FILL extent; no product IDs or device-resolution branches occur in the application ABI. Physical display rotation and raw-touch rotation come independently from the existing presentation-profile provider. Safe insets bound content; captured drags keep signed content coordinates beyond the visible region. Raw contact-ID space follows the underlying uint8 contact protocol, not a new universal contact quota.

MONO1 uses the public contract's one=white convention and explicitly converts to the display API's one=black convention. RGBA8 preserves straight-alpha, sRGB-channel content on RGB565 panels by source-over composition on an opaque white canvas, then panel quantization. This is not linear-light blending. RGBA8 on a monochrome-selected profile is explicitly UNSUPPORTED, never silent monochrome conversion. The physical background and letterbox are white.

Only one foreground session can own the physical presentation/input at a time. Logical leases and physical submitted frames are distinct. Receipts are retained dynamically until forgotten. Before submitting a later frame, the provider settles/caches the prior physical token outcome because existing physical providers may expose only their latest token. Pending presentation provides retryable backpressure, not a fixed frame-rate limit. COMPLETE/SUPERSEDED settle physical custody; physical FAILED/unknown do not, and retain the invocation. No queued frame is freed as cancellation.

Quiesce refuses an outstanding writable lease, waits for presentation settlement, then releases touch subscription/navigation foreground claims. Resume reacquires input and requires a fresh snapshot. A geometry change emits GEOMETRY_CHANGED and invalidates input interpretation; gap recovery uses a copied snapshot with its event cut. Native authority is checked after every external callback. Logical buffer initialization, physical clear and raster rows cooperate without per-pixel health calls. Revocation causes no subsequent provider call or allocation free.

`test_canvas_provider.py` rebuilds normal and ASan/UBSan tests for geometry, frame custody, capability lifecycle, malicious callback revocation and the actual ABI-v2 entry. Lower display/touch/navigation are controlled fixtures. `build_canvas_services.py` builds the actual Xtensa provider twice with the pinned compiler support archive, checks byte identity and native ELF structure, and records all local headers. Optional touch/navigation grant variants use the same ELF. CI archives results and packages. Host tests and target ELF validation are not physical device, panel-performance or firmware-release acceptance.

Consumer migration, actual product binding and physical input/raster/performance acceptance remain separate existing tracked work. This publication does not install firmware or replace a user's running device image.

Provider startup validates and binds descriptors before any application invocation exists; it does not require invocation authority or call the physical dependencies. Actual capability methods still require live authority. `test_canvas_runtime.py` exercises this distinction through the existing Runtime/ProviderGraph, real module loading and capability grant: three delayed presentations, quiesce/resume, receipt forgetting, close and clean return. It uses a modeled physical display and does not claim target instruction execution or hardware acceptance. CI runs this integration normally and with ASan/UBSan in addition to the lower-capability tests.
