# Opt-in linked-app text policy

`PORTABLE_TEXT_INPUT_POLICY` restores lifecycle work while a shared text-input session owns the display and input. It is selected only for the repaired Timecard profiles. Existing clients compile without the new path; no host ABI, manifest authority, native firmware or service behavior changes.

The app enables the existing checkpoint suffix. Capture-only Contexts work brackets each host poll. At settled host boundaries the linked adapter advances the predecessor's broadcast and Contexts model/rule work without reading touch, USB or navigation. Routine policy preserves the host's passive input. A Contexts workflow message temporarily borrows fully detached foreground focus and returns to the same copied editor draft.

On Watch, a prepare result distinguishes a routine low-battery sample from a possible idle sleep. The mode remains fixed through pause retries. A routine dispatch cannot become sleep because time or saved settings changed in between. Actual sleep keeps the adapter touch subscription closed; only the host resumes input, with a focus-change fence.

On X4, a successful resident POLL with exactly POLICY_REQUEST | INPUT_CONTINUITY is the only continuity promise. Older owners use full detachment. POLICY receives no app touch or mutable raster custody. An incompatible reply, retained boundary or failed resume is terminal; it cannot dispatch POLICY a second time. A clean EXIT closes the paused editor without resuming its scene.

Qualification is owned by Productivity's `scripts/test_timecard_policy.py`, using the real Timecard controller, this adapter and the text host with deterministic scene/device boundaries. The existing shared-input suite separately covers fields, persistence, Home, failures and non-keyboard render/storage parity. These are host-machine tests; physical power, radio and target timing require hardware qualification.
