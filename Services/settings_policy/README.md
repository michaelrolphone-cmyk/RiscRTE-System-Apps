# Explicit shared Settings policy provider

`service.c` exports `settings.policy@1` using the ordinary provider ABI. It has no hardware names, probes, mutable state, device fallback or dependency authority. Generate `settings_policy_config.h` with `scripts/generate_shared_settings_policy.py POLICY.json OUTPUT_DIR`; compile this provider against the same canonical staged SDK and Settings headers as the application. Every semantic field must be supplied. The deployed manifest must register one unique authorized provider and grant Settings `settings.policy@1` instance 0. This work does not publish or install that composition.

The included semantic selections preserve existing source options, not hardware classifications:

- `calendar-desk-segments.json`: existing `PORTABLE_SETTINGS_X4_DESK_CLOCK`, native calendar editing, sleep and alarm settings, atomic storage and availability; no paper/resident direction or timer option. `settings.inc` fixes Light/Deep mask 3 and Light default 0. `PortableDeskClockSettings.h` chooses Segments 0 without Points. Calendar RTC instance 0 still requires unique authorized capability.
- `native-desk-points-lock.json`: existing native-only desk, resident-shell Points face, Home desk-lock, visual-only alarm, namespace preferences, availability and idle timer selections. Points is stable face ID 6 and requires `PORTABLE_DESK_POINTS_FACE` in the shared application/model build. Sleep preference remains preserved but non-editable under desk lock.
- `native-touch-hybrid-timers.json`: existing native-only touch profile plus `--sleep-settings --sleep-timer-settings`, visual-only alarm and namespace preferences/availability. Generic sleep fallback is Hybrid (2), mask 7. Face, flip, language and desk direction are absent in that existing selection.

Sources: `scripts/build_portable_settings.py`, `scripts/settings_sleep_defaults.py`, `lib/PortableApps/src/settings.inc` (sleep/defaults/rows), `PortableDeskClockSettings.h` (face default), `PortableSleepPolicy.h` (60-second idle / 300-second subsequent Deep defaults). None of these JSON files is selected automatically. Explicit configured `--default-sleep-mode` or `--default-idle-seconds` deployments require matching JSON values instead of these baseline selections.

Live-apply limitation: these read-only providers declare persistence-only behavior (`apply_features=0`). Existing foreground idle cache update `portable_foreground_idle_timeout_changed()` is app-local, not an existing provider capability. The existing resident host POLICY checkpoint reloads `pqa_session_load(&quick,rt)` before idle crossing/sleep decisions and then returns CONFIGURATION_CHANGED. A correctly wired shared child can use that existing path without a new idle capability. POLICY is requested by host POLL at idle due or the five-second sample interval, not an immediate save acknowledgement. Shared-app/host integration still needs a dedicated witness before parity claims. A non-resident deployment requiring immediate idle changes must bind the existing app-local callback explicitly. The runtime descriptor supports a declared apply mask and callback; callback failure reports saved-but-apply-unconfirmed. No provider fakes successful live apply.

Qualification: actual Alarm editor service is exercised by `scripts/test_shared_settings_runtime.py`. Host modeled broker/storage/clock tests are not physical-device proof. Clock SetTime helper currently runs a bounded synchronous transaction; wall-clock latency/frame responsiveness remains to be qualified. Production ELF manifest/signing/admission, remaining RTC/atomic fault combinations beyond the 10 covered cases, native presentation/physical input and lifecycle reentry require integration qualification.
